# 国内大模型 API 价格与选型参考（2026-08-24 核对版）

> 本文只比较厂商官方 API，不比较网页会员、Coding Plan、云市场转售、私有化部署或限时赠送额度。
> 价格会频繁调整；上线前必须再次查看链接中的官方价格页。

## 统一口径

- 价格单位均为 **人民币元 / 百万 tokens（MTok）**。
- “输入”指缓存未命中的普通输入；缓存命中价单列。
- 同一模型可能按地域、上下文长度、服务等级或促销活动分档，下表只列中国大陆/全球服务中最常用的公开档位。
- 不能只比较输入价：Agent 和思考模型可能产生大量输出 tokens，实际费用应按下式计算：

```text
费用 = 未缓存输入 tokens × 输入单价
     + 缓存命中 tokens × 缓存价
     + 输出 tokens × 输出单价
     + 搜索、缓存存储、语音等附加费用
```

### 缓存的作用范围

缓存命中价只有在缓存真的命中时才成立，而命中条件比直觉严格得多。被缓存的是 KV 张量（注意力层的 key/value），它是模型权重的函数，因此：

- **按模型隔离，不按厂商。** 同一厂商的不同模型之间不共享缓存；同一模型的不同版本快照、不同量化或部署方式也各自独立。阿里云对此有明文：“缓存数据存在模型间隔离，不会共享。”
- **按账号隔离。** 阿里云：“无论是隐式缓存还是显式缓存，数据都在账号级别隔离，不会共享。”
- **按地域/部署隔离。** 价格既然按地域分档，缓存也不跨地域复用。
- **前缀必须从位置 0 完整匹配。** DeepSeek 明确：请求为 `A+C` 而缓存单元为 `A+B` 时不命中。系统提示词或工具定义改动一个字，其后全部失效。
- **有 TTL，且不保证命中。** DeepSeek 称缓存“几个小时到几天”后自动清空，且系统是“尽力而为”，不保证 100% 命中；阿里显式缓存 TTL 为 5 分钟，每次命中重新计时。

由此得到两条实践推论：

1. **任何切换模型的行为都会让缓存全部作废**，包括限流 fallback、按时段切换配置、以及在同厂商内换型号。估算成本时不能把切换当成零成本操作。
2. **提高命中率的唯一有效手段是稳定前缀**：把系统提示词、工具定义、项目常量放在最前面并保持不变，易变内容（当前文件、对话历史）放后面。

隐式缓存与显式缓存的计费机制不同。以阿里为例：隐式自动生效且无法关闭，写入按标准输入价、命中约按标准输入价的 20%；显式需主动创建，写入按 125%、命中按 10%、TTL 5 分钟。智谱另按“缓存存储”（元/百万 tokens/小时）单独计费，MiniMax 的缓存写入也单独计价。读表时必须先确认某一列指的是哪一种。

### 示例成本口径

为了提供一个可复算的数量级，本文使用：**100 万未缓存输入 tokens + 25 万输出 tokens**。
这不是能力或性价比排名，只是价格示例；长思考任务的输出比例通常更高。
DeepSeek 按空闲/高峰两档计价，其示例成本写成「空闲 / 高峰」两个值。

### 表格注记

1. DeepSeek 官方页按**高峰 / 空闲**两档计价：空闲价为高峰价的一半，高峰时段为北京时间周一至周五 9:00–12:00 与 14:00–18:00，其余为空闲时段。三个模型均为 1M 上下文、最大 384K 输出。请注意其输出单价远高于输入单价（flash 为输入的 3 倍），长输出的 Agent 任务实际成本会明显高于按输入价的直觉估计。`reasoning_effort` 会改变推理长度和实际输出量，但它是用量参数，不是价格档位。
2. Qwen 价格按地域和上下文分档明显，不同部署地域不能直接混算。表中 Flash 是华北2（北京）的 ≤32K 档，另有 32K–256K 为 0.6/2.4、256K–1M 为 1.2/4.8；Agent 场景很容易越过 32K，应按实际上下文估算。Plus 使用核对日页面显示的限时八折价（原价 2/8）。Max 使用**中国大陆（华北2 北京）**档 12/36；国际档（新加坡、美国、德国、日本）为 14.988/44.965。表中缓存列为**隐式缓存**估算值（约标准输入价的 20%）；官方表述为“标准输入单价的 20%”，未说明促销期间是按原价还是折后价计算，`qwen3.7-plus` 因此给出 0.32–0.40 的区间。需要确定性命中时应改用显式缓存（写入 125%、命中 10%、TTL 5 分钟），计费方式完全不同。
3. `doubao-seed-evolving` 与 `doubao-seed-2-1-pro` **不按上下文分档**，全程 6/30/1.2（另有缓存存储 0.017 元/百万 tokens/小时）。Evolving 上下文 1M、最大输出 256K、最大思考内容 256K，TPM 100 万、RPM 500，支持文本/图片/视频输入、Function Call、联网搜索、知识库、MCP 与显式+隐式缓存，且用**固定 model ID** `doubao-seed-evolving` 周级自动升级，不需要迁移。它默认思考很重（实测回复「OK」消耗 309 输出 tokens，其中 292 是 reasoning），而 reasoning tokens 按输出价计费，简单任务应通过 `thinking.type` / `reasoning_effort` 调低。官方另有「体验奖励计划」可减免 20% 调用成本，属于限时活动，不应写进长期预算。
4. 火山引擎按上下文分档：表中为 ≤32K 基准价，32K–128K 约为基准价的 1.5 倍，>128K 约为 3 倍；服务方式和缓存存储可能产生额外价格。API model ID 使用连字符形式（`doubao-seed-2-0-pro`），不是产品页展示的 `Doubao-Seed-2.0-pro`。旧的 `doubao-lite-32k`、`doubao-pro-32k` 不再作为本表主推矩阵。
5. MiniMax M3 与 M2.7 标准档当前恰好同价：M3 的刊例价经官方“永久五折”后为输入 2.10、输出 8.40；M2.7 标准档也是 2.10/8.40。同价不表示能力相同。新项目应默认先测 M3；M2.7 主要用于既有项目兼容或回归对照，因此不在主表重复列出。M3 输入超过 512K 后为输入 4.20、输出 16.80、缓存读取 0.84；M3 优先服务为标准服务的 1.5 倍。
6. Kimi 官方文档已明确列出 API model ID：`kimi-k3`、`kimi-k2.7-code`、`kimi-k2.7-code-highspeed`、`kimi-k2.6`、`kimi-k2.5`。HighSpeed 变体为标准档的两倍价（输入 13.00、输出 54.00、缓存命中 2.60），输出速度约 180 tokens/s。Kimi 页面更新较快，切换模型前仍建议用 List Models API 复核可用性。
7. 腾讯混元原平台正逐步迁移至 TokenHub；免费额度属于有期限、有限量的体验资源包（自开通起 1 年内未用完即作废），不等于永久零成本。
8. 智谱不只有旗舰一款。当前矩阵至少包括免费文本模型 `glm-4.7-flash`、低成本高速模型 `glm-4.7-flashx`、高智能文本模型 `glm-4.7`、文本旗舰 `glm-5.3`（2026-08-14 发布，与 `glm-5.2` 同价同上下文，官方称编程能力较 5.2 提升约 50%）、上一代旗舰 `glm-5.2`、多模态 Coding 模型 `glm-5v-turbo`，另有 `glm-5.1`、`glm-5-turbo`、`glm-5`、`glm-4.6v` 等中间档位以及图像、视频、语音等专用模型。GLM-4.5 等旧系列正在下线迁移，不再作为新项目首选。
9. `glm-4.7` 按单次请求长度分档：输入 <32K 且输出 <0.2K 时为输入 2、输出 8、缓存命中 0.4；输入 <32K 且输出 ≥0.2K 时为 3/14/0.6；输入 32K–200K 时为 4/16/0.8。表中采用更符合 Agent 长回复的第二档。`glm-5v-turbo` 输入 ≥32K 时为输入 7、输出 26、缓存命中 1.8。智谱缓存存储目前限时免费，不能视为永久价格。

## 如何做真正的性价比比较

不存在脱离任务的统一“价格指数”。建议使用自己的请求日志，至少分三类压测：

| 工作负载 | 建议记录 |
| --- | --- |
| 路由/抽取 | 成功率、JSON 合法率、P95 延迟、每千次成本 |
| 日常 Agent | 工具调用成功率、平均轮数、输入/输出 tokens、任务完成成本 |
| 复杂代码/研究 | 一次完成率、人工返工时间、总输出 tokens、搜索等附加费 |

同一批固定任务至少重复 20 次，再比较：

```text
有效任务成本 = API 总费用 / 成功完成的任务数
```

低单价模型如果需要更多轮重试，最终成本可能高于单价更贵但一次完成率更高的模型。

## 面向 Pi 类 Agent 的初始候选

- **低成本路由与清洗**：先测 `qwen3.7-flash`、`doubao-seed-2-0-mini`、`glm-4.7-flashx`；`glm-4.7-flash` 免费档可用于压测但需自行验证生产限额。注意 `deepseek-v4-flash` 输出 4.50–9.00，不属于这一档。
- **日常主力 Agent**：先测 `qwen3.7-plus`、`MiniMax-M3`、`glm-4.7`；`deepseek-v4-pro` 能力强但输出单价高，应按实际输出量核算再决定。
- **代码与长程任务**：先测 `glm-5.3`、`deepseek-v4-pro`、`kimi-k2.7-code`；是否值得使用 `kimi-k3` 应以任务完成率验证。
- **拟人化回复**：不要仅凭厂商品牌判断。用相同人设、记忆和安全约束，对 MiniMax、Kimi、Qwen 等做盲测。
- **联网搜索**：把搜索工具调用费、搜索结果质量和引用正确率单独统计；“模型擅长联网”通常也依赖厂商工具，而不只是基础模型。

## 维护规则

- 每次更新价格时同步修改标题中的核对日期。
- 只使用厂商官方价格页，并保留链接。
- 新增价格必须写清币种、MTok、地域、上下文档位、缓存状态和促销条件。
- 时段计价（如 DeepSeek 的高峰/空闲）必须写出两档价格和时段定义，不能只取其中一档。
- 缓存价必须注明是隐式还是显式，并记住缓存按模型和账号隔离——换模型即全部作废，不能跨行复用。
- 不再使用无法复算的“价格指数”，也不写“95% 能力”“最强”“无可替代”等无测试依据的结论。
